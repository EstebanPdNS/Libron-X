# Manual resource collections

Open **Library → Collections** to create and rename a collection, select one or several resources, add them, and remove individual members. **Show in library** selects the collection and clears text/facet filters; later filters compose with membership. Collections can contain any resource format. Their names describe a topic, author or purpose. Manual collections retain explicit members; rule-based collections calculate matching members from the current catalog.

Definitions live in the app-owned `resource-collections.json`, separately from parallel Bible groups and source books. Each member retains its resource path, format, legacy identifier and display title. Missing or hidden members remain in the definition; only available exact identities appear in the library. A file at the same path with a different format or identifier does not silently replace a member.

The versioned snapshot validates names, unique IDs, standardized absolute paths and bounded membership before committing an atomic write. Malformed/future state cannot be overwritten; external edits require an explicit reload. Bulk additions commit together and reject duplicates. Bounds are 256 collections, 8192 members each and 160 UTF-16 units per name.

Validation: 636 tests in 107 suites, including five collection tests covering mixed-format persistence, filtering/visibility, missing editions, invalid edits, bulk overflow, corrupt state and concurrent writes. Installed build 29 was exercised with LSF, LLS and e-Sword resources, a Greek/emoji name, native multi-selection, library filtering, normal restart and member removal. The existing Bible-group state was byte-identical; 1099 payload/index/normalized-content hash checks across 521 resources passed. Native visual observation covered Spanish and dark appearance; other appearance/layout combinations remain unobserved in this checkpoint. This does not assert complete equivalence with original Libronix collections.


## Rule-based collections

**New rule-based collection** creates a separate collection with a valid “title has a value” rule. Select all/any conditions, add or remove conditions, inspect the preview and explicitly save rules. Unsaved changes are labeled and can be reset; showing the collection in the library requires the saved rule. Invalid drafts cannot be saved. Manual collections cannot be silently converted or modified through rule APIs.

The 19 fields cover title/aliases, author, language, source format, resource type, category, tags, publisher, year, series, origin, file name, subtitle, contributors, edition, original year, biblical coverage, subcategory and abbreviation. Conditions support contains, equality, prefix, negative contains/equality, present and missing. Matching folds case, diacritics and character width with a fixed locale; language values use the catalog's canonical code aliases. Multi-value positive comparisons match any value; negative comparisons require known values and reject if any value matches. Missing metadata needs an explicit “no value” condition. Values are bounded to 512 UTF-16 units; each rule has 1–32 uniquely identified conditions. No scripts, regex execution, filesystem inspection or original executable is involved. Derived bibliographic metadata retains its existing inference limits.

Membership is computed from immutable catalog values rather than flattened into stored members. Imports and metadata changes therefore update library filters, previews and subsequent searches automatically. A running search retains its submitted source snapshot. Search scopes union manual and calculated membership by stable resource identity and keep hidden requested matches as explicit omissions; library previews show visible matches. No collection rule changes resource bytes or parallel Bible groups.

Existing manual schema-1 state loads without a write. A mixed snapshot with rules uses schema 2, and a manual-only snapshot uses schema 1. Rule collections must have no explicit members; malformed, unknown or incompatible rule state blocks saving. Atomic writes and stale-writer protection remain shared with manual collections. Removing the last rule collection preserves all manual definitions.

Build 42 native acceptance covered creating/renaming/saving a two-condition rule, invalid-draft rejection, all/any preview discrimination, reset, a zero-to-one membership update after importing an authored EPUB through the native file chooser, library filtering, normal restart and source-bound search/navigation. The 720-test / 119-suite regression includes eight new rule tests: all metadata fields, missing values, Boolean modes, schema compatibility, imports/metadata changes, manual preservation, visibility, search snapshot isolation, invalid/corrupt edits and concurrent writers. Ten user-state files and the exact library catalog/entry set were restored after testing; the authored package remains only in private evidence. Native visual evidence covers the current Spanish dark interface; light, RTL and older macOS were not manually observed. This checkpoint does not establish complete original Libronix rule-syntax equivalence.
