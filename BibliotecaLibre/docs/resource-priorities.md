# Resource priorities and key links

Open **Tools → Key links** and choose Bible, commentary, dictionary or lexicon, then the query language. Enter a Bible reference or an indexed headword. **Search** enumerates successful destinations; **Open preferred** opens the first configured number of successful resources. Missing entries and failed reads do not consume a successful-result slot. Failures remain visible separately. Cancelled or superseded work cannot open late destinations.

**Priorities** keeps three independent settings: ordered promoted resources, enabled defaults, and an opening count from 1 to 8. Promote, remove, move, enable/disable and reset operate only on the chosen type/language. Promotions never duplicate a resource. Hidden or missing members remain in the definition and are omitted from automatic lookup. The library's explicit dictionary choice, a reference's explicit edition and a designated Bible reference target retain precedence over automatic priorities.

A language inherits that resource type's general definition until edited. The editor displays these effective values; the first edit copies the inherited definition before applying the change. Later general edits do not replace that explicit language definition. Reset removes only the selected definition and resumes inheritance, or defaults for the general scope. This preserves promoted resources when changing only the opening count or one checkbox.

Available candidates use catalog resource types. For dictionary/lexicon languages, original embedded `data-types` / `keylink=yes` declarations take precedence over the book's bibliographic language; otherwise catalog languages determine eligibility. Promoted resources precede enabled defaults. Default ordering uses a POSIX-folded title with the exact stable resource ID as a tie-breaker, independently of interface language. This is a deterministic native policy; it does not assert the original engine's ranking algorithm.

Bible links resolve real reader references. Dictionary and lexicon links resolve actual indexed headwords and physical articles. e-Sword commentary lookup checks source Book/Chapter/VerseCommentary rows, chooses the narrowest containing verse range, then a chapter or book introduction. Equal ranges retain source row order. These articles retain their physical identity and are never relabelled as Bible text. A missing Bible verse is not treated as a successful chapter hit.

`resource-priorities.json` is app-owned versioned state, separate from books, collections, Bible groups and documents. Writes are validated and atomic; stale writers require reload. Resource identities retain path, format and legacy identifier. Lookup captures source, companion, manifest and normalized-database stamps. Opening checks those stamps again, uses an independent native reader and verifies the decoded text fingerprint where applicable.

Validation includes independent source-row fixtures for overlapping commentary ranges, four resource kinds, raw/normalized sources, Unicode headwords, dictionary precedence, disabled defaults, inherited settings, reset, corrupt state, write conflicts, missing/changed sources, cancellation and superseding requests. Original KeyLink action registries, original summary continuation limits, morphological datatypes, display/hover preferences and full original workflow equivalence retain their separate acceptance gates.
