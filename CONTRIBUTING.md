# Contributing

Start with [development](docs/development.md) and [architecture](docs/architecture.md). Discuss large feature changes in an issue first.

Keep changes focused. Explain the problem, resulting behavior, compatibility and checks in the pull request. Preserve native macOS controls and original source-format semantics. Add meaningful regression coverage when changing decoding, persistence or request ownership.

Bug reports should include the version, macOS version, Mac architecture, reproduction steps, expected result and actual result. Attach a screenshot or sanitized diagnostic only when useful. Do not upload commercial resources, license data, personal notes, raw decompiler output or credentials.

Run the relevant Swift tests and build the current app before submitting. State which private-corpus or manual checks were not run.
